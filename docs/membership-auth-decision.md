# 회원 단계 인증 결정

## 확정 결정 (2026-10-11)

사용자가 선택지 ①을 명시 승인했다: **포털 계정과 NAS 계정을 분리한다. 웹 가입 → 관리자 승인 → NAS 계정 연결** 순서로 진행한다.
DSM 비밀번호로 포털에 로그인하지 않는다. 이 리뷰에서는 인증·회원 코드를 구현하지 않으며 부모가 후속 구현을 위임한다.

## 비교한 선택지

| 선택지 | 경계 및 결과 | 상태 |
|---|---|---|
| ① 독립 포털 계정 + 승인 후 NAS 연결 | 포털 인증/승인과 NAS 계정·프로비저닝 상태 분리. DSM 비밀번호를 포털 로그인에 사용하지 않음 | 사용자 선택 확정 |
| ② DSM 자격증명으로 포털 로그인 | DSM 인증 API·MFA·잠금·장애 정책 확인 및 NAS 자격증명 취급 필요. 포털 승인 경계는 별도로 필요 | 선택하지 않음, 구현 금지 |

## 후속 구현의 수용 기준

- 포털의 가입/로그인/복구 정책과 NAS 연결 절차 분리. DSM 비밀번호를 포털 비밀번호로 수집·저장·로그인 검증하지 않는다.
- 가입 직후 pending 상태이며 관리자 승인 전 NAS 및 타 회원 정보 접근 거부.
- 승인과 NAS 계정 연결은 별도 상태 및 감사 기록. 승인 성공만으로 NAS 연결 성공을 표시하지 않는다.
- tenant+membership 기준 접근 통제, 교차 tenant 객체 조회·역할 상승·중복 승인 거부 테스트.
- 승인 취소/정지 시 세션과 권한 캐시 무효화, 관리자 재인증/MFA 및 로그인 rate limit 정책.
- custom User 채택 여부와 첫 앱 migration 설계는 회원 구현 전에 결정한다. 현 내장 auth 테이블은 일회 개발 DB 기반이며 운영 데이터가 있다고 가정하지 않는다.
- NAS 계정 연결은 외부 ID 매핑/소유 확인/관리자 승인 기준을 정한 후 구현. 실제 NAS 계정 생성·권한 변경은 별도 승인 필요.

이 결정은 인증 방식만 확정한다. NAS 모델/API/그룹 quota, 회원 개인정보 보존·삭제, 배포 대상, 실제 NAS 변경 권한은 여전히 미결정이다. 1단계 전체 승인이나 3단계 구현 완료로 계산하지 않는다.
