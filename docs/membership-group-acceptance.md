# 고객사 그룹 관리 — 확정 요구와 후속 수용 기준

2026-10-11 추가 사용자 지시. **요구 확정, 아래 확대 구현은 아직 미완료**. 기존 부분 회원 기능 또는 PR 병합으로 수용했다고 계산하지 않는다. 3단계 전체 수용/후속 PR 병합은 새 기준 검증과 부모 최종 확인 전 보류한다.

## 확정 역할과 안전 경계

- 전역 admin 아래 고객사 그룹(tenant)별 관리계정을 지정한다.
- 가입자는 고객사 그룹을 지정해 신청한다. 사용자 제출 그룹은 신청 대상일 뿐 자동 소속 승인/접근권이 아니다. 신청 대상과 승인된 권한의 혼동을 막아야 한다.
- 배정된 그룹관리자는 자신의 그룹 신청 승인과 계정 폐기를 수행하고 타 그룹/전역 권한을 변경할 수 없다.
- 전역 admin만 그룹 총 용량과 최대 계정 수 한도를 설정한다. 그룹관리자는 할당받은 범위 내 자율 관리하며 최대치 자체를 수정하지 못한다.
- 계정 폐기는 우선 포털 접근 비활성화 + 모든 세션 폐기 + 감사 유지다. NAS 파일/계정 실제 삭제는 금지. 파괴적 삭제 의미는 별도 승인 대상이다.
- 관리자 MFA는 전역/그룹 관리자 모두에 적용해야 한다. 비밀번호 재인증만으로 충족하지 않는다.
- NAS 모델 미정은 개발 차단 사유가 아니다. 공식 최신 정식 DSM 기준 개발과 실장비 지원능력/모델별 검증 게이트는 구분한다.

## 반드시 새로 구현·검증할 항목 (모두 미충족)

| 수용 기준 | 필요한 검증 | 현재 부분 구현과의 차이 |
|---|---|---|
| 전역 관리자만 그룹관리자 지정/교체 | 그룹관리자/일반회원의 역할·tenant 위조 거부; 지정 감사 | 신뢰 CLI bootstrap만 있음 |
| 그룹 선택 신청 + 승인 전 차단 | 존재하지 않는/비공개/타 그룹 입력, pending 직접 URL, 신청 후 tenant 변경 | 현재 공개 가입은 tenant 미배정 |
| 그룹관리자의 자신의 그룹 승인/폐기 | 교차 그룹 객체/검색/POST 모두 거부; 재인증+MFA | 현재 scoped 승인/취소만 일부 검증 |
| 총 용량·최대 계정 수 설정 | 전역만 변경, 음수/비정수/overflow, 한도 축소 정책, 감사 | 관련 model/UI/정책 없음 |
| 동시 승인 최대 계정 초과 방지 | 마지막 1자리에서 2개 동시 승인 중 최대 1개 성공; rollback 후 count 일치; 실제 운영 DB 경합 | 현재 조건부 update는 각 회원 중복만 방지 |
| 계정 폐기 접근 차단 | DB 비활성화, 기존/복원/동시 로그인 session 차단, idempotence, 감사 유지 | suspended 회원은 재로그인 가능 |
| 자기 폐기·마지막 그룹관리자 보호 | 자신의 폐기 거부; 두 관리자 동시 상호 폐기/마지막 관리자 교체 경합 | 자기 객체만 현재 거부; 마지막 관리자 보호 없음 |
| 관리자 철회와 진행 중인 변경 직렬화 | 철회 transaction과 actor 권한 검사/변경이 정의된 순서대로 완료; revoked actor 후속 write 없음 | actor 행 잠금 없는 조회, 실경합 미검증 |
| 그룹 총 용량 강제 집행 | 포털 예약/할당 합계 제한과 NAS 실제 quota 강제 집행 각각 검증; 부분 실패 보상 | quota/adapter 미구현, NAS 매핑은 단순 식별자 |
| 비밀·감사 보호 | OTP/복구/비밀번호가 로그/감사/오류 보고/CI에 없음 | 감사 allowlist 및 일부 POST 오류 필터만 검증 |

## 구현 전 명확히 해야 하는 정책

- 최대 계정 수가 approved 활성 계정만 세는지, 그룹관리자/전역 계정/신청 대기/폐기 계정을 어떻게 다루는지 확정. 임의 count 정의로 ‘한도 보장’ 주장 금지.
- 한도를 기존 할당/사용량보다 낮출 때 거부/유예/초과 표시 정책. 파일 자동 삭제 또는 무단 NAS quota 변경 금지.
- 마지막 그룹관리자를 교체/폐기할 전역 관리자 절차와 비상 복구. 단순 root 예외로 감사/MFA를 우회하지 않는다.
- 그룹 총 용량이 사용자 quota 합계인지, 공유폴더 실제 사용량/그룹 quota인지 명확히 구분. 장비 확인 전 이 값을 같은 것으로 취급하지 않는다.
- MFA secret 저장·device 최초 등록/복구 정책은 `evidence/membership-security-review.md`의 결정 항목 참조.

## 인계 범위

현재 리뷰 커밋은 기존 로그인 rate limit 두 우회 및 커스텀 view 오류 보고 POST 비밀 노출만 수정했다. 신규 요구용 가짜 통과 테스트/skip/expectedFailure로 완료를 꾸미지 않는다. 부모가 위 항목별 RED→GREEN 및 운영 DB race 검증을 이어간다. 이메일 검증·웹 비밀번호 복구는 메일 대상 확정/실제 전달 검증 전 배포 게이트로 유지한다.
